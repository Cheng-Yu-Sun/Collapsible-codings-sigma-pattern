# Collapsible Codings and the Sigma-Pattern

R code for *A Unified Framework for Multi-Scale Stratification in Space-Filling Designs via Collapsible Codings*, by Cheng-Yu Sun, Shao-Wei Cheng, and Frederick Kin Hing Phoa.

## Start here

The repository includes Figure 2, Tables 2–6, and the saved numerical results used to produce them. Choose the workflow that matches your purpose:

1. **View the supplied results:** open the PDF in [Figures/](Figures/) or the CSV files in [Tables/](Tables/). No R computation is needed.
2. **Recreate figures and tables from saved results:** open `GitHub_Sigma.Rproj` in RStudio and run only the relevant output section described below. These sections use base R and do not rerun the searches or GP simulations.
3. **Rerun the computations:** install the packages listed below, open the corresponding R script, and run all its lines. Full runs regenerate and replace the corresponding saved results; GP simulations and larger design searches can take substantial time.

The project file sets the working directory to the repository root. Without RStudio, set the working directory to this folder. Entry scripts also recognize subfolders up to three levels below the root.

To use the supplied results, run only the **Plotting section** of `R/Section 5/Figure2.R`, the **Table section** of `R/Section 5/Table3_benchmarks.R`, or the final **Paper table** section of the relevant Table 4–6 script. Table 2 can be regenerated by running all of `R/Section 5/Table2_search_summary.R`. Start these output sections with the repository root as the working directory. They read the saved inputs and rewrite the corresponding figure or table outputs.

| Result in the paper | R script | Final output |
|---|---|---|
| Figure 2: self-defined test function | `R/Section 5/Figure2.R` | `Figures/Figure2.pdf` |
| Table 2: SOA search summary | `R/Section 5/Table2_search_summary.R` | `Tables/Table2.csv` |
| Table 3: benchmark prediction results | `R/Section 5/Table3_benchmarks.R` | `Tables/Table3.csv` |
| Table 4: 16-run four-level regular designs | `R/Section 6/Table4_regular_4level_16run.R` | `Tables/Table4.csv` |
| Table 5: 64-run four-level regular designs | `R/Section 6/Table5_regular_4level_64run.R` | `Tables/Table5.csv` |
| Table 6: 81-run nine-level regular designs | `R/Section 6/Table6_regular_9level_81run.R` | `Tables/Table6.csv` |

Each full entry script can be run from a new R session. When run in full, Figure 2 runs the two self-defined-function simulations, and Table 3 runs the two benchmark-function simulations. Table 2 reads the supplied search scores. Tables 4–6 run their regular-design searches. No SOA search or benchmark-design generation is needed before the GP simulations: the design matrices are supplied.

Figure and computed-table outputs are created when their scripts are run. `Figures/` holds one complete PDF per figure; `Tables/` holds one CSV file per table (Tables 2–6). Numerical results and intermediate calculations go in `detailed_outputs/`. The four benchmark functions produce Table 3, without boxplots.

Table 3 gives mean NRMSEs (three decimals), with standard deviations in parentheses in units of 0.001 (one decimal). Its `z` column identifies the two design settings. The numerical means, standard deviations, and replicate counts are also saved in `detailed_outputs/simulations/benchmark_summary.csv`.

## Packages

Tables 4–6 use base R. The GP simulations use `doSNOW`, `foreach`, `hetGP`, `LHD`, and `TestFunctions`. SOA searches use `lpSolve`, `doSNOW`, and `foreach`. Generating the benchmark designs also needs `SFDesign`, `SLHD`, and `MaxPro`. The `parallel` package comes with R.

The locally installed R and package versions, recorded on 2026-10-23 during repository preparation, are listed in [environment-info.txt](environment-info.txt).

```r
install.packages(c("doSNOW", "foreach", "hetGP", "LHD", "TestFunctions",
                   "lpSolve", "SFDesign", "SLHD", "MaxPro"))
```

## Run one simulation setting

The four simulation scripts are separate and all source `sim_setup.R`:

| Setting | Script in `R/Section 5/` |
|---|---|
| Self-defined function, z = 4 | `self_defined_z4.R` |
| Self-defined function, z = 6 | `self_defined_z6.R` |
| Four benchmark functions, z = 4 | `benchmark_z4.R` |
| Four benchmark functions, z = 6 | `benchmark_z6.R` |

Run any one of these to save its NRMSE matrices and print the mean NRMSEs. The defaults are 300 independent replicates and 10,000 test points, with `(z,N,m) = (4,32,15)` or `(6,72,13)`. Each replicate uses one random level expansion, one common column permutation for the six design classes, and a common test LHD. There is no averaging over repeated column permutations within a replicate.

All GPs use `hetGP::mleHomGP()` with `covtype = "Matern5_2"` and the package's default optimization settings. All design columns enter the GP fit, including the inactive factors. The four benchmark responses are log-transformed. NRMSE is the square root of the mean squared prediction error divided by the test-response variance, calculated with divisor `N.test`.

For a short trial, reduce `n_rep` near the top of the relevant simulation script. `N.test`, `seed`, and `n_cores` are also set there. The default worker count is the detected core count minus two, with a minimum of one. Each replicate receives its own seed. Numerical optimization can vary with package versions.

Using the supplied NRMSE matrices, or after rerunning the self-defined simulations, run only the **Plotting section** of `Figure2.R` to draw the complete figure without refitting. Similarly, the **Table section** of `Table3_benchmarks.R` reads the saved benchmark results. Run these sections with the repository root as the working directory. Figure 2 uses separate vertical scales for z = 4 and z = 6; the two limits can be set in its plotting section. Outlier symbols are hidden, but all replicates enter the boxplot statistics.

GP simulations, optimized benchmark generation, and the larger regular-design searches can take substantial time. For an initial trial, Table 2 gives a short entry point. A reduced `n_rep` gives trial results, not the full paper calculation.

## Examine or reproduce a step

| Step | Script |
|---|---|
| SOA search, z = 4 | `R/Section 5/best_array_search/Search_SOA_z4.R` |
| SOA search, z = 6 | `R/Section 5/best_array_search/Search_SOA_z6.R` |
| Class (iii): uniform LHDs | `design_matrices/class_iii/Uniform_LHD.R` |
| Class (iv): random LHDs | `design_matrices/class_iv/Random_LHD.R` |
| Class (v): maximin LHDs | `design_matrices/class_v/Maximin_LHD.R` |
| Class (vi): MaxPro LHDs | `design_matrices/class_vi/MaxPro_LHD.R` |

Each of these is a Run All entry. SOA searches replace the corresponding two SOA files in `design_matrices/` and save their scores in `detailed_outputs/best_array_search/`. Each benchmark generator replaces its two lists, one for each z. Each supplied list contains 300 designs; regenerate longer lists before increasing `n_rep` beyond 300. Rerunning a generator can give different designs from the supplied fixed inputs.

For z = 4, Sigma uses 100 starts for each of the 144 choices of A. SP screens all 144 choices by sigma33 before optimizing B for the minimizer. For z = 6, Sigma uses 100 random permutations plus identity; SP screens 1,000 random permutations. Each retained permutation receives 50 B starts. The parameters and seeds are near the top of each search script. Sigma searches run in parallel; SP searches run sequentially. Table 2 reports time spent initializing and optimizing B, excluding permutation screening and worker startup. Its CSV lists the numbers of A arrays considered and retained in separate columns; times and scores are rounded to two decimal places.

The helpers are loaded automatically; there is no need to run them separately:

| Helper | Contents |
|---|---|
| `R/Section 5/sim_setup.R` | One simulation replicate, GP fitting, NRMSE, and parallel repetitions |
| `R/Section 5/best_array_search/soa_z4_functions.R` | z = 4 scores, admissibility constraints, initialization, and column updates |
| `R/Section 5/best_array_search/soa_z6_functions.R` | Corresponding functions for z = 6 |
| `R/Section 6/regular_design_functions.R` | Finite-field operations, word ranks, and pattern comparisons |

Tables 4–6 save their numerical results as RDS files in `detailed_outputs/regular_designs/`. To export the supplied results without searching, run the final **Paper table** section of the relevant script from the repository root. The CSV files give the generating matrix and separate `n1`, `n2`, and `n3` columns. The `search_type` column identifies the partial searches used for 6–10 factors in Table 6.

## Supplied inputs

`design_matrices/` contains the four fixed SOAs, the regular 32-run catalog, the 36-run ternary OA, and the benchmark LHD lists. The SOAs are saved as R matrices with levels starting at zero.

`regular_32run_catalog.txt` lists ten additional columns for each of the 144 regular arrays; the code adds the five basic columns. The catalog was computed by the authors using the search method described in Chen, Sun, and Wu (1993).

`OA_36_13_3_2.csv` comes from [N. J. A. Sloane's orthogonal array library](https://neilsloane.com/oadir/oa.36.13.3.2.txt).

`detailed_outputs/` includes the saved SOA search scores, final regular-design search results, and NRMSE matrices for the self-defined and benchmark functions. The four simulation scripts regenerate the corresponding NRMSE matrices. Output folders are created as needed, so empty folders need not be retained by Git.
